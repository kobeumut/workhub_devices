### Scope of the regressions

- `packages/core/test/talkSync.test.ts`: multi-room total based on the server snapshot; no local increment caused by own/repeated messages; remote-client read, room removal, and reconnect reconciliation; an old in-flight snapshot after a read is not applied; serial/monotonic visible read marker, retry after an error, stop, and late-result isolation; `Retry-After` for room/heartbeat/read; heartbeat cleanup and stopping when support is missing.
- `packages/core/test/presence.test.ts`: `includeStatus`, `noStatusUpdate`, `setReadMarker=0`; explicit `user_status` capability, old version/missing support; credentials-scoped heartbeat route, argument validation; raw/OCS errors and unknown presence text.
- Mobile `talkActivity.test.tsx`: in the shared hook, unread 3 → background → reconnect and 0; forwarding the same total to the native badge; no heartbeat during 120 s in the background; rejecting a late stale result on account switch; on unmount, badge 0 and no backend calls on subsequent timer ticks. `activity.test.ts`: on blur of the Android notification shade, the activity is stopped even if AppState stays active; focus and subscription cleanup.
- `chatViewability.test.js`: using the installed RN FlatList viewability algorithm: a message three times taller than the screen, a fully visible short row, and an offscreen row; based on viewport coverage, the long message can also be read. The 300 ms minimum visibility time is retained.
- These hook/core/algorithm tests are not evidence of native FlatList hit-testing, screenshots, a real OS badge, or two-device/push behavior.

### API and lifecycle contract

Verified upstream contracts: [Talk conversation](https://nextcloud-talk.readthedocs.io/en/latest/conversation/), [Talk chat](https://nextcloud-talk.readthedocs.io/en/latest/chat/), Nextcloud `user_status`, and the Talk stable25 sources. `GET room?includeStatus=true&noStatusUpdate=true` returns a read-only snapshot; history and long-poll fetches use `setReadMarker=0`, so the fetch itself does not mark messages as read. Read is sent only for the server message ID that the FlatList actually reports as visible in an active/focused ChatView; the detail panel/background does not trigger it. After a successful read, the central room list is fetched again. Fetching lists or opening a room is not, by itself, a read.

Status support is fail-closed on `user_status.enabled` and a supported Nextcloud major >=25; there is no heartbeat on an old/missing version. `PUT /ocs/v2.php/apps/user_status/api/v1/heartbeat` sends only `status=online`. The server computes activity and preserves the manual invisible/dnd preference; the client does not use the `status` preference setter and does not write offline on cleanup (so as not to set another active client offline). On a supporting server, a heartbeat is sent immediately per foreground account session and then every 60 s; the room snapshot is fetched every 5 s. Background, focus loss, account switch, and sign-out stop the timers/subscriptions. On a network error the last unread count is kept but the cached online label is hidden; the error is shown, and the next poll/resume reconciles again. The server rate-limit duration is respected. The manual visibility preference was not verified with a live counterpart in this branch.

### Native badge / gap matrix

`PlatformServices.setBadgeCount(count)` uses the same server unread total of the active account; totals of other accounts are not added. It is cleared on zero, sign-out, and account cleanup; on resume it is refreshed from the server. Negative, fractional, and overflowing values are rejected at the native/IPC boundary. There is no new dependency or OEM launcher broadcast.

|---|---|---|
| Shared UI | Chats tab, room counter; accessibilityLabel on room/title/participant status | Automated core/hook tests exist; real OS accessibility and FlatList visibility test **unverified** |

**Remaining gaps:** the app does not do JS poll/heartbeat in the background; the OS icon total is not recomputed at the moment a push arrives in the background (it is reconciled on resume). In an open/focused room, the existing native foreground-route filter suppresses notifications; local unread is not incremented from the push payload. The closed/cold-start and real FCM/APNs side of push suppression was not verified in this branch. If an old Talk server lacks the `noStatusUpdate` / read-marker suppression parameters, server behavior is not guaranteed. Full lists are fetched every 5 s; a delta optimization for large accounts was deferred. No additional server change was made.

## GENE-59 — Known issues (Android keyboard, LogBox), Android emulator tour, Linux packages (3 November 2026)

Root cause (keyboard): Android 16 enforces edge-to-edge; `adjustResize` does not shrink the window. `KeyboardAvoidingView` (RN 0.88) computes the overflow from the frame of `onLayout` **relative to the parent** (`frame.y + frame.height - keyboard.screenY`); because the top inset of the root `SafeAreaView` and the header did not enter this calculation, the input area was left under the keyboard by that amount. The other screens (form, task) had no avoidance at all. Fix: a single Android keyboard spacer in the mobile shell (`keyboardDidShow` height = `ime - systemBars`, the root is already padded by the navigation bar height → total = IME), KAV only on iOS.
