# Workhub module matrix (Devices client)

Source: Workhub 0.5.0 (`a359a4c`), API v1. Test: Nextcloud 35.0.2 dev server, users `alice`/`bob` (staff), `carol` (restricted). Status values:

- **Native**: the screen exists in the app and was verified against a live server.
- **Native (partial)**: the basic flow exists; the listed operations are on the web.
- **Web fallback**: the web UI on the user's own server is opened. This does not count as natively complete.
- **Web (approved administration flow)**: Nextcloud admin operations deliberately left on the web, with the rationale written in "Administration decision" below. After GENE-56 this is the only flow that goes to the web.
- **Gap**: no API on the server.

The Gate column lists `GET /capabilities` → `modules.*` (per user, fail-closed) and admin status.

## Administration decision (GENE-56)

**Decision:** Workhub administration is not built natively; the **Tasks → Administration** tab, visible only to Nextcloud admins, opens the Workhub admin settings on the user's own server in the system browser. User approval was requested in the issue; until approval arrives this row counts as "awaiting approval".

**Rationale (verified live, 2 November 2026, dev server):**

1. All of Workhub's admin write endpoints (`AdminFeaturesController::update`, `AdminAiController::update`/`deleteSecret`, `AdminTimeController::updatePolicy`, `WorkloadController::updateSettings`, `AdminDeckImportController::start`) carry `#[PasswordConfirmationRequired]`.
2. The app uses a per-device **app password** via Login Flow v2. With the admin account's app password, `PUT /admin/features` and `PUT /admin/ai/provider` → **403 "Password confirmation is required"** (a temporary app password was created, tried and revoked).
3. The same request only succeeds when the admin's **actual password** is sent with Basic auth. Nextcloud's password confirmation (`/login/confirm`) requires a browser session; there is no confirmation flow for OCS/app passwords. Native administration would mean the app takes the admin's main password (and sends it on every request or stores it) — which contradicts the rule in PLAN.md that the main password is never taken or stored, and the issue's requirement that "the admin password is not stored in the app".
4. The read endpoints (`GET /admin/features`, `/admin/ai/provider`, `/admin/ai/usage`, `/admin/time/policy`) do not require password confirmation; but a read-only native screen would still send the user to the web for changes and would create two separate administration surfaces. For this reason it was not added (it can be opened as a separate task if requested).

**Outcome:** After this slice, the only flow that goes to the web is this approved administration flow. A normal user has no "More"/"Administration" tab; all other user modules, including AI and linking a task to a time entry, are native.

**Outcome:** The day-to-day workflow is native: project creation/renaming, column and member management, goal sharing, task listing, creation, opening, moving, completing, field editing, assignment with a person picker, subtasks, dependencies, comments, assignment notifications, timer, time entry CRUD, period submission/withdrawal, manager review, team report and CSV, request creation, request response (approve/reject), resolving without a task, converting to a task, request history and report, goal creation/editing, target value CRUD, check-in and history, task ↔ goal linking and ownership transfer; project Gantt, activity feed and workload matrix; dashboard/widget CRUD, results, drilldown, CSV and dashboard sharing (GENE-54); workflow templates (create, step editor, activate, share, delete), run start/cancel, handoff, retry, skip and run history (GENE-55). The Gantt (read-only timeline), the project activity feed and the workload matrix are also native (GENE-53). AI (GENE-56: status/quota, summary, question, task draft, edit and subtask suggestion, cancel, history, draft accept/reject) and linking a task to a time entry (GENE-56) are native. The only flow that goes to the web is Workhub administration by Nextcloud admins (the approved administration flow, above). Items that are native but partial are listed as "Open item (client)", not as a web fallback: drag-to-position on the workflow canvas, drag-to-schedule in the Gantt, drag-to-arrange layout in the dashboard and some filter pickers; for this reason "full Workhub native" is not claimed yet.
