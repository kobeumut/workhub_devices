# Workhub modül matrisi (Devices istemcisi)

Kaynak: Workhub 0.5.0 (`a359a4c`), API v1. Test: Nextcloud 35.0.2 dev sunucusu, kullanıcılar `alice`/`bob` (staff), `carol` (kısıtlı). Durum değerleri:

- **Native**: uygulama içinde ekran var ve canlı sunucuda doğrulandı.
- **Native (kısmi)**: temel akış var; listelenen işlemler web'de.
- **Web fallback**: kullanıcının kendi sunucusundaki web arayüzü açılır. Bu, native tamamlandı sayılmaz.
- **Gap**: sunucuda API yok.

Gate sütunu `GET /capabilities` → `modules.*` (kullanıcı bazlı, fail-closed) ve yönetici bilgisidir.

Proje paylaşımı Workhub'da ayrı bir "share" nesnesi değildir: sunucu `objects/{type}` için yalnız `dashboard`, `goal`, `workflow` kabul eder (`ShareController::TYPES`). Projeye erişim üye ekleme ile verilir.

**Sonuç:** Günlük iş akışı native: proje oluşturma/yeniden adlandırma, sütun ve üye yönetimi, hedef paylaşımı, görev listeleme, oluşturma, açma, taşıma, tamamlama, alan düzenleme, kişi seçicili atama, alt işler, bağımlılıklar, yorum, atama bildirimleri, zamanlayıcı, zaman kaydı CRUD, dönem gönderme/geri çekme, yönetici incelemesi, takım raporu ve CSV, talep oluşturma, talep yanıtlama (onay/red), görevsiz çözme, göreve dönüştürme, talep geçmişi ve raporu, hedef oluşturma/düzenleme, hedef değer CRUD, check-in ve geçmişi, görev ↔ hedef bağlama ve sahiplik devri. Yönetim ve analiz modülleri (dashboard, Gantt, iş yükü, iş akışları, AI, admin) ve düzenleme alt akışları şimdilik web fallback. Bunlar açık iş olarak duruyor ve "tam Workhub native" denmiyor.
